# ADR-0010: 生成と読み取りを WebMCP のツールとして公開する

- 状態: Accepted
- 日付: 2026-09-06
- 関連: [ADR-0003](0003-rust-core-dual-target.md) / [ADR-0007](0007-feature-colocation.md) / [ADR-0009](0009-stay-on-workers-free.md)

## 文脈

qrcc の中心機能である生成と読み取りは、すでに端末内の wasm だけで完結している
（[ADR-0003](0003-rust-core-dual-target.md)）。WebMCP（`document.modelContext`）は
この client-side のロジックを、そのままブラウザ内の AI エージェントに「ツール」
として差し出すための W3C の API で、**サーバを 1 行も書かずに**エージェント
対応ができる。追加の Worker リクエストも D1 書き込みも発生しないので、
無料枠の制約（[ADR-0009](0009-stay-on-workers-free.md)）とも衝突しない。

これが入ると、エージェントが DOM を推測してクリックを模倣する代わりに、
`generate-code` / `decode-code-image` を関数として直接呼べるようになる。

**重要な前提**: WebMCP は 2026-09 時点で **Origin Trial 段階**であり、既定では
どのブラウザでも有効になっていない（Chrome 149 / Edge 150 が Origin Trial、
Firefox と Safari は標準化ポジションの表明のみ）。

## 決定

- **生成と読み取りだけをツールにする。** 保存・一覧・共有はツールにしない
- **Origin Trial トークンは登録しない。** API が無い環境では何もしない
  （挙動が一切変わらないことをテストで固定する）
- **`exposedTo` は使わない。** 既定の「同一オリジンの文書とブラウザ組み込み
  エージェントにのみ公開」の範囲から出さない
- **読み取りツールは `data:` URL のみ受け付ける。** `fetch` は使わず、
  `https:` などの任意 URL を取得する経路を持たせない
- **v1 のツールは画面の状態を動かさない。** 計算して結果を返すだけ

## 理由

### 生成・読み取りは追加コストゼロで公開できる

生成と読み取りは端末内で完結し、認証も副作用も無い。Worker も D1 も消費しない
（[ADR-0003](0003-rust-core-dual-target.md) / [ADR-0009](0009-stay-on-workers-free.md)
と整合）。ツールの `inputSchema` は `PAYLOAD_KINDS` / `SYMBOLOGY_KINDS` から
組み立てるので、対応する内容の種類や符号が増えてもツール側の直書きは要らない。

### 保存・一覧・共有は出さない

保存系は認証が要り、**エージェントが利用者の確認なしに共有リンクを作れる経路**
になる。WebMCP は「利用者がその場にいる」ことを前提にした API ではないので、
副作用のある操作を無条件に公開するのは危険が大きい。ツールにしたくなったら、
先に認可の設計をやり直すこと。

### `data:` URL 以外を読み取りツールに通してはいけない

読み取りツールが任意の URL を取得できると、**利用者のブラウザを踏み台にして
社内ネットワークや認証付きリソースを読ませられる**（SSRF に類する経路）。
`fetch` そのものを実装から無くすことで、将来の改変でも経路が生まれないように
してある。

### Origin Trial トークンを今回は登録しない

トークンはオリジンごと・期限つきで、失効すると静かに無効になる。2026-09
時点でまだ 1 ブラウザ（系列）でしか有効化できず、運用コストに見合わない。
「API があれば登録し、無ければ何もしない」形にしておけば、仕様が正式化した
ときに変更なく自動的に効き始める。

## 帰結

- API が無い環境（2026-09 時点ではほぼ全て）では何も起きない。
  コンソールにエラーも出ない
- 仕様が正式化したら、この ADR を見直して Origin Trial トークンの要否を
  再確認する。**黙って有効化しない**
- 次の一手は `GenerateScreen` の状態をリフトアップして、ツールから画面を
  直接操作できるようにすること。それには画面の状態管理の変更が要るため、
  この決定からは意図的に外してある
- `webmcp-types`（npm、2026-09 時点で 0.x）には依存しない。自前の最小構造型
  を使う。将来使うなら完全固定バージョンで入れること
