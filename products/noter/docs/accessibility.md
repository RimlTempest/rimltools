# アクセシビリティ

目標は **WCAG 2.2 AAA**。到達できない項目は「なぜ無理か」と「代替」を
ここに書き残す。書き方の規約は `.claude/skills/noter-html-a11y` を参照。

## 1. 方針

- **セマンティクスが先、ARIA は最後。** `<button>` / `<dialog>` / `<details>` /
  `<output>` で表せるものに `role` を書かない
- **色だけに頼らない。** 接続状態はテキスト（ステータスピル）で、
  参加者の識別は色 + 名前で、診断はアイコン + 行番号 + 本文で伝える
- **キーボードだけで全操作できる。** コードエディタも例外にしない
- **動きは控えめに。** `prefers-reduced-motion` で全アニメーションを止める
- **共同編集の通知はうるさくしない。** 参加・離脱・再接続は 1 つの
  `aria-live="polite"` 領域にまとめて、同じ意味の通知を連発しない

## 2. AAA 達成計画

| 達成基準                         | 対応                                                                                                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1.1 非テキストコンテンツ       | mermaid 図は `<svg role="img" aria-label>` + ソースを `<details>` で併記。装飾アイコンは `aria-hidden`                                                                                      |
| 1.3.1 情報と関係性               | 診断は `<ul>` に `<li>` で行番号・重大度・本文。参加者は `<ul aria-label="参加者">`                                                                                                         |
| 1.4.3 / 1.4.6 コントラスト (AAA) | 本文 7:1、大きな文字 4.5:1。`DESIGN.md` のトークンで担保し、`bun run a11y` の axe（`wcag2aaa` タグ）で検証                                                                                  |
| 1.4.8 視覚的提示                 | 行長 80 文字以内（プレビュー）、行間 1.5、段落間 2 倍、ユーザーが 200% に拡大しても横スクロールしない                                                                                       |
| 1.4.10 リフロー                  | 320px 幅でエディタ・プレビューを縦積みに切替（container query）                                                                                                                             |
| 1.4.12 テキストの間隔            | 行間・字間をユーザー CSS で上書きしても崩れない（固定高さを使わない）                                                                                                                       |
| 2.1.1 / 2.1.3 キーボード (AAA)   | 全機能をキーボードで操作可。ドラッグ操作（分割ペインのリサイズ）にはキーボード代替（表示モードボタン）を用意                                                                                |
| 2.1.2 キーボードトラップなし     | CodeMirror は既定で Tab を捕まえない。Tab インデントは **Esc の後 Tab で脱出**できる方式（`indentWithTab` を有効にする場合は必ず併記）                                                      |
| 2.2.1 タイミング調整             | 時間制限なし。セッション期限（30 日）は操作で延長される                                                                                                                                     |
| 2.2.6 タイムアウト (AAA)         | オフライン・切断中も編集はローカルに保持され、再接続で送信される。データが失われる条件（デプロイによる切断など）は無い                                                                      |
| 2.3.1 / 2.3.3 (AAA) 光過敏・動き | 点滅なし。カーソルのフェードのみ、`prefers-reduced-motion` で停止                                                                                                                           |
| 2.4.3 フォーカス順序             | ヘッダ → ツールバー → エディタ → プレビュー → ステータス、の DOM 順                                                                                                                         |
| 2.4.7 / 2.4.13 フォーカスの外観  | `--noter-focus` の 3px リングを全要素に。エディタ内のカーソルも同色                                                                                                                         |
| 2.4.8 現在位置 (AAA)             | `<title>` に文書名、パンくず（ホーム / 文書名）                                                                                                                                             |
| 2.4.9 リンクの目的 (AAA)         | 「共有リンクをコピー」「Raw を開く」など動詞つきラベル                                                                                                                                      |
| 2.5.5 / 2.5.8 ターゲットサイズ   | 44×44px 以上（`--noter-tap`）                                                                                                                                                               |
| 2.5.7 ドラッグ操作               | 分割ペインのリサイズにはボタン代替（エディタのみ / 分割 / プレビューのみ）                                                                                                                  |
| 3.1.5 読解レベル (AAA)           | UI の文言は短い和文。専門語（CRDT など）を画面に出さない                                                                                                                                    |
| 3.2.5 要求による変化 (AAA)       | 文書の自動保存以外に、操作なしで画面を変える要素を置かない。他者の編集で**自分のカーソル位置は動かさない**                                                                                  |
| 3.3.1 / 3.3.3 エラーの特定と修正 | 診断は行番号 + 何が悪いか + 直し方。クリックで該当行へ移動                                                                                                                                  |
| 3.3.4 / 3.3.6 エラー回避 (AAA)   | 削除・共有リンク失効は確認ダイアログ。文書は削除後も 30 日は復元可能（`deleted_at`）                                                                                                        |
| 3.3.7 冗長な入力                 | ゲスト名は 1 度入力したら記憶する                                                                                                                                                           |
| 4.1.3 ステータスメッセージ       | 接続状態・保存状態・参加者の増減を **1 つの** `role="status"` 領域で通知。同時に複数出さない                                                                                                |
| 1.4.4 テキストのサイズ変更       | 文字サイズを 200% にしても横スクロールが出ない（寸法は `rem` / `em` で組む）。`e2e/tests/manual-checks.spec.ts` が幅 640px × 文字 200% で検査                                               |
| 1.4.11 非テキストのコントラスト  | `forced-colors: active` で境界線を `CanvasText` に戻す（ピル・パネル・上限バナー）。同 spec が axe で検査                                                                                   |
| 2.2.6（上限到達）                | `rejected(limit)` / `rejected(too_large)` でも入力は続けられ、書き出しを促すバナーを出す（`ux.md` §6.5）。読み上げは既存の 1 つの `role="status"` に任せ、バナー自体は live region にしない |

## 3. 到達困難な項目

| 達成基準                      | 状況                                                                                                                                                                                                                                                                                                                                |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.1.3 / 3.1.4 / 3.1.6 (AAA)   | ユーザーが書く文書本文（略語・読み方）は制御できない。UI の文言のみ対象                                                                                                                                                                                                                                                             |
| 1.4.8（本文の行長）           | エディタ側はユーザーの文書なので行長を強制しない。折り返しは既定で有効                                                                                                                                                                                                                                                              |
| mermaid 図の代替テキスト      | 図の意味を自動で言語化できない。`aria-label` は「mermaid 図（N 個のノード）」に留め、ソースを併記する。手動で説明文を書くための記法は将来の課題                                                                                                                                                                                     |
| リモートカーソルの読み上げ    | 他者のカーソル位置を逐次読み上げると使えなくなる。`aria-hidden` にし、参加者リストで「誰がいるか」だけ伝える                                                                                                                                                                                                                        |
| 4.1.3（オフライン復帰の通知） | 回線が戻ったあと、ピルと読み上げが「再接続しています」のまま止まることがある。ブラウザが `online` を報せても、生きたままの WebSocket からは新しい `status` が来ないため（データは失われず、編集は届く）。直すには `features/sync/client` の状態遷移を変える必要があり、plan 008 の範囲外。`e2e/tests/resilience.spec.ts` に注記あり |
| 読み上げソフトでの確認        | VoiceOver / NVDA の読み上げは自動化できない。`.claude/skills/noter-html-a11y/references/manual-checks.md` §3 のとおり人が確認する。機械で確かめられるぶん（キーボードのみ・200% 拡大・動きの停止・ハイコントラスト）は `e2e/tests/manual-checks.spec.ts` にある                                                                     |

## 4. 検証

```bash
bun run a11y          # Playwright + axe-core（wcag2a / wcag2aa / wcag2aaa / wcag21aa / wcag22aa / best-practice）
bun run markuplint    # 静的なマークアップ検査
```

`e2e/tests/a11y.spec.ts` が全画面を開き、axe の違反が **0 件**であることを
確認する。エディタ画面は接続前（`connecting`）・接続後（`connected`）・
拒否（`rejected`）の 3 状態で検査する。

手動チェックの手順は `.claude/skills/noter-html-a11y/references/manual-checks.md`。

## 5. 画面ごとの注意

| 画面           | 注意点                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| ホーム         | 文書一覧は `<ul>`。種類（markdown 等）はバッジ + テキスト。「新規作成」は `<button>` で `<a>` ではない（副作用があるため） |
| エディタ       | `EditorView.contentAttributes` で `aria-label="本文"`、`aria-multiline`。プレビューは `<section aria-label="プレビュー">`  |
| 共有ダイアログ | `<dialog>` を使い `showModal()`。ロール選択は `<fieldset>` + `<legend>`。コピー結果は `<output>`                           |
| サインイン     | ゲスト名入力は `<label>` 明示。Google ボタンは環境に資格情報が無いとき描画しない（隠すのではなく出さない）                 |
| 印刷           | `@media print` でエディタ・ツールバー・参加者を隠し、プレビューだけを流し込む                                              |

## 6. 更新ルール

- 新しい画面・コンポーネントを足したら、この表に行を足す
- AAA に届かないと判断したら §3 に理由と代替を書く。黙って AA に落とさない
- axe の違反を `disableRules` で消さない。消すなら理由を §3 に残す
