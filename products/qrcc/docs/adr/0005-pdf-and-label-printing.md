# ADR-0005: ラベル印刷はブラウザ印刷が主、PDF は Rust で生成

- 状態: Accepted
- 日付: 2026-09-01

## 文脈

要件は「pdf印刷・ラベル印刷」。ラベルは市販台紙（A4 24 面など）にミリ単位で
合わせる必要がある。日本語キャプションも入る。

Rust で PDF を生成する場合、日本語フォントの埋め込みが必要になる。
Noto Sans JP のフルセットは数 MB あり、Workers の 10MB 圧縮上限と
起動時間を圧迫する。

## 決定

**2 経路を用意し、既定はブラウザ印刷。**

1. **ラベル印刷（主経路）**: `@media print` + `@page` + CSS Grid によるブラウザ印刷。
   - フォントは OS のものを使うため日本語で困らない
   - アクセシビリティ（読み上げ・拡大）が印刷プレビューでも維持される
   - サーバリソースを一切使わない
2. **PDF ダウンロード（副経路）**: `crates/qrcc-print` が `krilla` +
   `usvg` で生成し、`qrcc-api` が返す。
   - フォントは R2 に置き、**使用文字だけをサブセット化**して埋め込む
   - wasm バンドルには含めない（[ADR-0003](0003-rust-core-dual-target.md)）

## 理由

- ブラウザ印刷は「フォント問題ゼロ・実装コスト最小・a11y 維持」の三拍子。
  ラベル台紙合わせは `@page` の `size` / `margin` と Grid で正確に表現できる。
- それでも PDF が要る場面（印刷業者への入稿、保存、共有）があるため副経路を残す。
- フォントを R2 に置けば wasm を小さく保てる。R2 は無料枠 10GB・エグレス無料。

## 帰結

- ラベル台紙定義（`LabelSheet`）は **CSS と PDF の両方が同じデータを読む**。
  定義元は `packages/core/src/print/sheets/`。二重管理しない。
- 印刷プレビュー画面は実際の `@media print` スタイルを iframe で表示し、
  「画面で見たものが印刷される」ことを保証する。
- PDF 生成は 10ms CPU に収まらない可能性がある。R2 にハッシュキーで
  キャッシュし、同一仕様の再生成をゼロコストにする。超過が続く場合は
  ブラウザ側 PDF（`qrcc-print` の wasm 版 + サブセットフォントの動的取得）へ
  移す余地を残す。
- フォントのライセンス（Noto = OFL）を `docs/licenses.md` に記載する。
