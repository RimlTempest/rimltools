# 無料枠の予算設計

**無料で運用できることが絶対条件。** 超えそうな箇所を先に潰し、
超えたときは課金ではなく**機能を縮退させる**方針。

前提として **Workers Free プランに留まり、従量課金される R2 は使わない**
（[ADR-0009](adr/0009-stay-on-workers-free.md)）。Workers Free は上限に達しても
課金されず、リクエストがエラーになって止まるだけ。つまり**この予算を外しても
請求は発生しない**。以下は「アプリが止まらないため」の設計であって、
「請求を抑えるため」の設計ではない。

## 1. 無料枠（2026-09 時点）

| リソース           | 無料枠             | 本アプリでの主な消費要因               |
| ------------------ | ------------------ | -------------------------------------- |
| Workers リクエスト | 100,000 / 日       | ページ表示、保存、一覧、共有リンク解決 |
| Workers CPU        | 10 ms / リクエスト | SSR、保存・一覧、サーバ側デコード      |
| D1 ストレージ      | 5 GB               | codes / users / sessions               |
| D1 行読み取り      | 5,000,000 / 日     | 一覧・検索                             |
| D1 行書き込み      | 100,000 / 日       | 保存・更新・セッション                 |
| Static Assets      | 無制限             | JS / CSS / wasm                        |
| Service Binding    | **追加課金なし**   | qrcc-web → qrcc-api                    |
| ~~KV~~             | —                  | **使わない**（ADR-0009）               |
| ~~R2~~             | —                  | **使わない**（ADR-0009。従量課金）     |

最も先に枯れるのは **Workers の 100k req/日**。次が **D1 の行書き込み 100k/日**。

## 2. 設計上の対策

### リクエスト数を減らす

| 対策                                                                                      | 効果                                 |
| ----------------------------------------------------------------------------------------- | ------------------------------------ |
| 生成・プレビューをブラウザの wasm で行う（[ADR-0003](adr/0003-rust-core-dual-target.md)） | 設定変更のたびのリクエストがゼロ     |
| 読み取りを端末側で行う                                                                    | 画像アップロードとデコード往復がゼロ |
| 静的アセットは Static Assets binding から配信                                             | Worker を起動しない                  |
| 一覧は loader でまとめて返す（N+1 の fetch をしない）                                     | 1 画面 1 リクエスト                  |

### キャッシュを足すときは Cache API から

KV も R2 も使わない（[ADR-0009](adr/0009-stay-on-workers-free.md)）。
将来キャッシュが要るとなったら、**Workers 内蔵の Cache API** を最初に検討する。
独自の無料枠を持たないので、この予算表を壊さない。

- 共有リンクの解決は索引の効いた D1 の 1 行読み取り（`share_link_code_idx`）。
  読み取り枠は 500 万行/日と潤沢なので、いまはキャッシュしない。
- レート制限は **D1 の 1 行 upsert**。Durable Objects は使わない。
- セッションは Better Auth の D1 ストレージに置く。

### D1 行読み取りを抑える

- 一覧は `LIMIT` + カーソルページネーション。`OFFSET` を使わない。
- `symbology` / `style` / `payload` を JSON 1 列に格納し、
  検索列だけを実列に出す（JOIN を減らす）。
- 一覧に必要な列だけ SELECT する（`CodeSummary`）。

### CPU 10ms を守る

- SSR は loader の並列取得で待ち時間を重ねる。
- **PDF はサーバで作らない。** 印刷はブラウザに任せる（[ADR-0005](adr/0005-pdf-and-label-printing.md)）。
- サーバ側デコードは「端末が対応していない形式」のみ。入口でサイズ上限
  （既定 4MB / 4096px）を課し、超過は 413 で拒否する。

## 3. 監視と縮退

`observability.enabled = true` を両 Worker に設定し、
日次で以下を確認する（`scripts/usage-report.sh`）。

| 指標             | 警告   | 縮退動作                                              |
| ---------------- | ------ | ----------------------------------------------------- |
| Workers req/日   | 70,000 | 未ログインの保存 API を一時停止し、ローカル保存を案内 |
| D1 行書き込み/日 | 70,000 | 履歴（`ScanEntry`）の記録を停止                       |
| D1 ストレージ    | 4 GB   | 期限切れゲストのデータを先に掃除する                  |

縮退はフラグ（D1 の `feature_flags` テーブル）で切り替え、
デプロイなしで反映できるようにする。

## 4. やらないこと

- **有料プランへの移行**（Workers Paid を契約しない / ADR-0009）
- **R2 の有効化**（利用上限を設定できず、従量課金が止められない / ADR-0009）
- **KV の利用**（用途が無くなった / ADR-0009）
- Durable Objects の常時利用（無料枠 100k req/日を別途消費するため、
  必要になったときに ADR を追加して判断する）
- Workers AI / Vectorize（現時点で用途がない）
- 画像の常時サーバ保管（既定でアップロード画像はサーバに残さない）
