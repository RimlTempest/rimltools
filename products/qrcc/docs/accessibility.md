# アクセシビリティ方針と WCAG 2.2 AAA 達成状況

目標は **WCAG 2.2 レベル AAA**。到達できない項目は理由と代替手段をここに記録する。
実装時の規約は `.claude/skills/qrcc-html-a11y/`。

## 1. 方針

1. 意味の合う HTML 要素を最優先。ARIA は補強にのみ使う。
2. 状態表現とレイアウトは CSS で完結させ、JS が落ちても主要機能が動く。
3. 生成したコードは**画像だけで提供しない**。必ず内容をテキストでも出す。
4. 自動チェック（oxlint jsx-a11y / markuplint / axe-core）は前提条件であって
   合格条件ではない。手動確認（`references/manual-checks.md`）を必ず行う。

| ------------------------------------ | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 1.2.6 手話 / 1.2.8 メディア代替      | 動画コンテンツを持たないため **非該当**                                       | —                                                                                                     |
| 3.1.4 略語                           | 「QR」「EC レベル」等は初出で `<abbr title>` + 用語集で対応                   | 用語集ページ                                                                                          |
| 3.1.6 発音                           | 日本語の同音異義が問題になる箇所は現状なし。発生したら `ruby` を使う          | —                                                                                                     |
| 1.4.6 コントラスト（ユーザー指定色） | **ユーザーが QR の色を自由に指定できる**ため、生成物自体は 7:1 を保証できない | 保存前にコントラスト比を計算し、閾値未満なら警告 + 修正候補を提示。UI 自体（周囲の文字）は 7:1 を維持 |

## 3. 検証

```
bun run lint        # oxlint jsx-a11y
bun run lint:html   # markuplint (a11y preset)
bun run a11y        # Playwright + axe-core (wcag2a, wcag2aa, wcag2aaa, wcag22aa)
```

CI は上記 3 つすべてを必須にする。加えて PR には
`.claude/skills/qrcc-html-a11y/references/manual-checks.md` の
チェック結果を貼る。

## 4. 更新ルール

- 新しい画面を追加したら、この表に「その画面で新たに関係する基準」を追記する。
- AAA を諦める判断は必ずこの文書に理由付きで記録する（口頭で決めない）。
